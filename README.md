# Zap

A small Windows tray utility that keeps your computer from going to sleep, without changing Windows' power settings. Pause or quit it and normal sleep behaviour returns.

Written in Rust: one small, self-contained exe with no runtime to install.

## Download

The latest build is always [`dist/zap.exe`](dist/zap.exe) in this repo. It's a single file with nothing to install; copy it somewhere permanent (for example `%LOCALAPPDATA%\Programs\Zap\zap.exe`) and run it from there. The first run turns on Start with Windows for that copy.

To update, quit Zap (right-click → Exit), copy the new `dist/zap.exe` over the old one and start it again. Your settings and autostart carry over because the path hasn't changed.

Don't run Zap day to day from `dist/` or the build folder: a running exe is locked, so the next build or commit can't replace it.

## Usage

Zap lives in the system tray as a white lightning bolt.

- **Click** the icon to pause or resume. While paused the bolt is dimmed, the tooltip reads "Zap: inactive" (otherwise "Zap: active"), and your PC sleeps normally.
- **Right-click** for the menu:
  - **Pause / Resume**
  - **Keep display on** (on by default): also stop the screen from turning off. On Modern Standby laptops a screen that turns off looks like sleep, which is why this starts on.
  - **Keep Teams active** (on by default): stops Microsoft Teams (and similar apps) showing you as Away. After 4 minutes with no keyboard or mouse input, Zap presses F15, a key almost no keyboard has and nothing uses, so it doesn't type or trigger anything. It never fires while you're using the PC, and can't while the screen is locked, so it works best with "Keep display on". Check your workplace's policy on activity tools before relying on it.
  - **Start with Windows** (on by default): runs `zap.exe` when you sign in, using the standard per-user `Run` registry entry, so it also appears in Task Manager's Startup apps. The very first time Zap runs, it turns this on for that copy of the exe, so run it first from where you want to keep it. After that your choice sticks, including turning it off in Task Manager. If you move the exe, tick it again to point at the new location.
  - **About Zap**
  - **Exit**: asks for confirmation (unless paused), then lets the computer sleep again.

Only one copy runs at a time. Your menu choices are remembered between runs; pausing isn't, so Zap always starts active.

## How it works

- **Staying awake:** Zap calls the Win32 `SetThreadExecutionState` API with `ES_CONTINUOUS | ES_SYSTEM_REQUIRED` (plus `ES_DISPLAY_REQUIRED` when "Keep display on" is ticked). Pausing clears the request.
- **Teams:** this doesn't count as user activity, so on its own it doesn't stop Teams going Away. "Keep Teams active" adds a 30-second timer that checks `GetLastInputInfo` and sends an F15 key press with `SendInput` once input has been idle for 4 minutes. Teams goes Away after 5. The timer only exists while the option is on and Zap isn't paused.
- **Footprint:** Zap waits on the Windows message queue, so it uses no CPU while idle (about 2 MB of memory).

### Where settings are stored

| Setting | Location |
|---|---|
| Keep display on | `HKCU\Software\Zap\KeepDisplayOn` (DWORD) |
| Keep Teams active | `HKCU\Software\Zap\KeepTeamsActive` (DWORD) |
| Start with Windows | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Zap`, plus your last choice in `HKCU\Software\Zap\StartWithWindows` (DWORD; missing means Zap hasn't run yet) |

To remove every trace of Zap, untick Start with Windows, quit it, delete `HKCU\Software\Zap` and delete the exe.

## Building

Requires Rust 1.90 or newer, plus a resource compiler for the icons and version details: `windres` from MinGW for the GNU toolchain, or `rc.exe` from the Visual Studio Build Tools for MSVC.

```bash
cargo build --release
```

The executable is written to `target/release/zap.exe` (or to the `target-dir` set in a local `.cargo/config.toml`).

The icons are generated by `tools/make_icon.py` (needs Pillow), which renders each size separately so the tray icon stays sharp. Version details shown in Explorer come from `Cargo.toml`.

### Versioning and keeping `dist/zap.exe` up to date

A pre-commit hook runs on any commit that changes the code, icons or Cargo files. It:

1. Bumps the patch version in `Cargo.toml` (0.1.4 → 0.1.5). For a bigger change, edit the version yourself (say to 0.2.0) in the same commit and the hook leaves it alone.
2. Rebuilds the exe and adds it to the commit as `dist/zap.exe`, so the exe always matches the source. The version shows in About Zap and in the exe's Properties.

Commits that only touch docs or tooling don't change the version. Amending a code commit bumps the version again, so fix the number by hand if that matters.

Enable the hook once per clone:

```bash
git config core.hooksPath .githooks
```
